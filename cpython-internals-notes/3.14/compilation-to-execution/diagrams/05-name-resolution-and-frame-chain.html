변수를 찾을 때 호출자 Frame을 올라가지 않는다

렉시컬 이름 조회 경로와 호출 스택의 Frame 관계는 서로 다른 개념이다
컴파일러가 이름의 종류를 정한다 → 그 결과로 opcode와 실행 시 조회 경로가 정해진다

일반 이름 조회: 정해진 경로로 바로 간다

실제 값은 실행할 때 바뀌지만, 어디에서 읽을지는 대부분 컴파일할 때 정한다.

호출 스택: caller 방향 관계

Python Frame 객체에서는 f_back으로 이 방향을 관찰할 수 있다.
c Frame · 현재 실행
↓ f_back / caller 방향
b Frame
↓ f_back / caller 방향
a Frame
일반 변수 조회에는 이 체인을 사용하지 않는다
↩ 함수 반환과 호출자 실행 재개
⚠ 처리되지 않은 예외 전파와 스택 되감기
⌕ traceback · debugger · profiler · inspect
def caller(): value = 100 return callee() def callee(): return value
→
callee의 value는 전역 이름으로 컴파일된다.

callee globals → builtins → NameError

caller Frame의 지역 변수까지 올라가지는 않는다.
정리: 이름 조회는 렉시컬 스코프가 정한 직접 경로다. Frame 체인은 호출·복귀와 예외·관찰을 위한 실행 관계다.
